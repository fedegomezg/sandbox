# Memoria de proyecto — Punta del Este, Uruguay

Espacio de trabajo para sistematizar ideas fragmentarias y aterrizarlas en un plan de
negocios defendible.

## Estructura

| Carpeta | Qué contiene | Estado |
|---|---|---|
| `00-intake/` | Fragmentos crudos del usuario + síntesis estructurada | 🟡 En captura |
| `01-contexto/` | Contexto estructural del mercado Punta del Este (agnóstico al proyecto) | ✅ v1 |
| `02-memoria/` | La memoria / plan de negocios propiamente dicho | ⬜ Pendiente |
| `03-financiero/` | Modelo económico-financiero, supuestos, sensibilidades | ⬜ Pendiente |
| `04-riesgos/` | Registro de riesgos, supuestos críticos y killer questions | ⬜ Pendiente |
| `99-fuentes/` | Fuentes primarias, citas y verificaciones | ⬜ Pendiente |

## Método

1. **Capturar** sin filtrar (`00-intake/fragmentos.md`).
2. **Estructurar** los fragmentos en hipótesis explícitas (`00-intake/sintesis.md`).
3. **Estresar** cada hipótesis contra el contexto estructural (`01-contexto/`) — sobre todo
   contra estacionalidad y dependencia macro argentina.
4. **Cuantificar** solo lo que sobrevivió al paso 3 (`03-financiero/`).
5. **Escribir** la memoria (`02-memoria/`) cuando haya números, no antes.

## Principio rector

Ningún número entra al modelo sin fuente. Ningún supuesto entra a la memoria sin estar
etiquetado como supuesto. La memoria no es un documento de venta: es una herramienta para
decidir si el proyecto se hace o no se hace.
